阶段 0：环境准备（第 1 天，半天）

来源：数据库内核学习路线 环境准备
目标：在你自己的 Windows 电脑上把 RMDB 编译跑起来，能跑测试、能启动数据库
仓库：C:\Users\yanha\Desktop\ob2026（你已经在 Windows 上有一份，但编译必须在 WSL 里）

一、为什么必须在 WSL 里编译？

RMDB 是 POSIX 代码（用 pread/pwrite、fsync、fork 等 Linux 系统调用），Windows 上无法编译。所以要在 Windows 里装一个 Linux 子系统（WSL2），在 Ubuntu 里编译运行。

你的情况：代码已经 clone 在 C:\Users\yanha\Desktop\ob2026。Windows 的 C:\ 盘在 WSL 里以 /mnt/c/ 挂载，所以 WSL 里访问它：

两个选择：

方案 做法 优缺点
A. 直接在 /mnt/c 下编译 在 WSL 里 cd /mnt/c/Users/yanha/Desktop/ob2026 && cmake -B build -S . 省事，但跨文件系统编译很慢（/mnt/c 是 9P 协议，IO 慢）
B. 复制到 WSL 家目录编译 cp -r /mnt/c/Users/yanha/Desktop/ob2026 ~/ob2026 再编译 编译快 3~5 倍，推荐；改代码要同步（或用 VSCode Remote-WSL 直接在 Ubuntu 侧编辑）

推荐方案 B，而且用 VSCode 的 Remote-WSL 插件直接打开 WSL 里的目录编辑——这样改代码、编译、调试都在同一侧，不用来回同步。

四、拉代码 + 编译 + 跑测试

如果报错，先看这三件事：

  1. CMake Error: ... compiler → g++ 没装好，重跑 sudo apt install build-essential
  2. 缺 flex/bison → 补装
  3. 编译报 error: 'xxx' was not declared → 可能是代码有更新，git pull 后再编译

五、跑测试 + 启动数据库

注意：rmdb 是前台进程，跑起来后终端会"卡住"（这是正常的，它在等服务）。要停掉按 Ctrl+C。

六、Windows 侧的工具

工具 用途
VSCode + Remote-WSL 插件 在 Windows 的 VSCode 里编辑 Ubuntu 侧代码（左下角绿色按钮连 WSL）
Windows Terminal 多标签终端，一个跑服务一个跑客户端，方便
赛题 PDF C:\Users\yanha\Desktop\ob2026\2026年全国大学生计算机系统能力大赛数据库系统设计赛-决赛赛题.pdf——决赛唯一权威规范，随时翻

七、常见坑（先打预防针）

  1. /mnt/c 下编译巨慢：9P 文件系统协议，IO 慢。要么复制到家目录，要么接受慢。
  2. 换行符问题：Windows 的 git 默认可能把 LF 换成 CRLF，导致编译报错（expected unqualified-id 之类）。如果遇到，在仓库里跑 git config core.autocrlf input 后重新 clone 或 git add --renormalize .。
  3. 端口被占：8765 被占时 rmdb 启动会失败，先 lsof -i :8765 看谁占着。
  4. 测试库目录残留：rmdb test_db 用的目录如果上次异常退出，可能残留损坏文件，删掉重建即可（rm -rf test_db，测试数据丢了无所谓）。

八、自测（完成标准）

  • [ ] cmake --build build 成功，无报错
  • [ ] ./build/bin/unit_test 全部通过（这是基线，以后每次改代码都要跑）
  • [ ] 能启动 rmdb test_db，用 rmdb_client 连上，执行 show tables; 有输出
  • [ ] 能建表、插入、查询一条数据

全部 ✅ 后进入 阶段一-C++基础。

阶段一：C++ 基础（第 2~7 天）

来源：数据库内核学习路线 阶段一
定位：目标不是"学会 C++"，而是能读懂 RMDB 代码。按优先级学，遇到不会的再查 cppreference。
仓库：C:\Users\yanha\Desktop\ob2026

一、必学知识点（按优先级）

★★★ 1. 指针、引用、内存

是什么：裸指针 char*、new/delete[]、深拷贝、悬垂指针、栈/堆内存。

仓库落点：src/record/rm_defs.h:48 的 RmRecord 是整个存储层的数据载体——char* data 指向一块堆内存，size 记录长度，allocated_ 标记内存是否归它所有。这个类就是路线图 2.3 练习 1 的标准答案：

要搞懂的三个问题（对着代码想）：

  1. 为什么拷贝构造要 new char[size] + memcpy，而不是直接 data = other.data？（浅拷贝 → 两个对象指向同一块内存 → 析构 double free）
  2. 为什么拷贝赋值要先检查 this == &other？（自赋值时先 delete 再拷贝就崩了）
  3. 为什么析构函数要判断 allocated_？（有的 RmRecord 只是"借用"别人内存的视图，不拥有就不能 delete）

检验：能说出 RmRecord r2 = r1; 和 RmRecord r2; r2 = r1; 分别调用哪个函数。

★★★ 2. 类与访问控制

是什么：class/struct 区别、public/private/protected、封装、友元 friend。

仓库落点：

  • src/defs.h:39 的 Rid（page_no + slot_no，行在磁盘上的地址）——最简单的 struct 例子
  • src/defs.h:63 的 RecScan——接口类
  • RmFileHandle（src/record/rm_file_handle.h）、IxIndexHandle（src/index/）——典型的"私有成员 + public 方法"封装：内部页号、bitmap 都藏起来，外部只调 insert_record / delete_record
  • Rid 里的 friend bool operator== 是友元运算符重载的写法

注意：RMDB 代码里 struct 成员默认全公开，这本身就是在告诉你"这堆字段只是数据载体，没有不变量要保护"。

★★★ 3. 继承与多态

是什么：基类、派生类、虚函数 virtual、纯虚函数 = 0、抽象类、virtual ~X() = default。

仓库落点（两个层次）：

  • 抽象接口层：src/defs.h:63 的 RecScan——三个纯虚函数 next() / is_end() / rid()，派生类（RmScan、IxScan）各自实现扫描逻辑
  • 执行器层：src/execution/executor_abstract.h:18 的 AbstractExecutor——全项目最重要的继承体系。注意两个细节：
    • virtual ~AbstractExecutor() = default; —— 基类析构函数必须 virtual，否则通过基类指针 delete 派生类时只调基类析构（内存泄漏）
    • virtual std::unique_ptr<RmRecord> Next() = 0; —— 纯虚函数，每个执行器（SeqScan/Insert/Update…）必须自己实现，这就是"火山模型"的接口

检验：能解释为什么 AbstractExecutor *e = new SeqScanExecutor(...); e->Next(); 调用的是 SeqScan 的版本（虚函数表/动态绑定）。

★★★ 4. STL 容器

是什么：vector、unordered_map、map、set、pair、迭代器。

仓库落点：

  • vector：RmFileHandle 里的记录缓存、AbstractExecutor::cols() 返回 const std::vector<ColMeta>&
  • unordered_map：缓冲池页表（page_id → Frame）、SmManager 的索引缓存
  • map：src/defs.h:55 的 coltype2str 里就用 std::map<ColType, std::string> 做枚举→字符串映射
  • std::make_pair：src/common/common.h:27，TabCol 的 operator< 用它比较两个字段

重点：容器元素存的是什么（值还是指针）决定了拷贝成本。

★★☆ 5. 智能指针

是什么：unique_ptr（独占所有权）、shared_ptr（共享所有权 + 引用计数）、make_unique / make_shared。

仓库落点：

  • executor_abstract.h:43：Next() 返回 std::unique_ptr<RmRecord>——执行器把记录"转移"给上层，无需手动 delete，天然防泄漏
  • src/common/common.h:39：Value 里有 std::shared_ptr<RmRecord> raw——AST 里多个地方共享同一块记录缓冲，引用计数保证最后一个使用者释放

检验：能说清"unique_ptr 为什么不能拷贝、只能 move"；shared_ptr 什么时候会析构底层对象。

★★☆ 6. 模板

是什么：函数模板、类模板、typename、std::enable_if（够读就行，不用会写）。

仓库落点：

  • src/defs.h:17：read_unaligned<T>——从字节流里安全读任意类型（用 memcpy 避免未对齐 UB），Deserialize 里就用它读 int
  • src/defs.h:25-37：给枚举类型重载 operator<</operator>> 的模板，用了 std::enable_if<std::is_enum<T>>——"模板元编程"入门，看得懂 std::enable_if 是干嘛的就行（限定只有枚举能匹配这个模板）

★★☆ 7. 函数对象 / lambda

是什么：lambda 表达式、捕获列表 [&]、std::find_if / std::sort 的第三个参数。

仓库落点：executor_abstract.h:47-50，get_col 里一个非常典型的用法：

[&] 按引用捕获外部的 target。排序比较器、回调全是这个套路。

★☆☆ 8. 字符串处理

是什么：std::string、c_str()、substr、find、std::move 进 string。

仓库落点：src/common/common.h 的 TabCol（两个 string 字段）、Value::set_str 里的 str_val = std::move(str_val_)（避免拷贝）。SQL 解析、协议编码全是字符串操作，但阶段一只要求"会用"。

这些不在路线图 2.2 表格里，但自测文件里全都有，不提前认识会卡住：

四、自测清单（带答案线索）

路线图的 3 条自测，怎么算"过"：

  1. 能读懂 rm_defs.h 和 common.h 的所有类型定义

    • 标准：不看注释，能说出 RmRecord 拷贝赋值做了什么（第 68~85 行：自赋值检查 → 释放旧内存 → 深拷贝）；能说出 Value 的 union 里 int/float 为什么能共存（同一块内存不同解释）；能说出 init_raw 里 *(int*)(raw->data) 在干嘛（把 int 按字节写进 char 缓冲）
    • 卡点提示：Condition 和 SetClause 就是 SQL 的 WHERE 和 SET 子句的内存表示，is_rhs_val 区分"右边是列还是值"

  2. 知道 unique_ptr 和裸指针的区别

    • 标准：能说出三条——所有权唯一、离开作用域自动 delete（RAII）、不能拷贝只能 move。裸指针不会自动释放，也没人知道它指向的对象是否还活着

  3. 能解释 vector::push_back 什么时候会拷贝/移动对象

    • 标准：① 容量不够时扩容，所有元素被搬到新内存（旧元素移动/拷贝）；② 传左值实参 → 拷贝，传 std::move(x) 右值 → 移动；③ 对 RmRecord 这种定义了拷贝构造但没定义移动构造的类，扩容时走拷贝（深拷贝，贵）；④ 所以存指针/unique_ptr 比存对象本身便宜
    • 进阶：这就是为什么执行器返回 unique_ptr<RmRecord> 而不是 RmRecord——移动廉价、拷贝昂贵

五、学习建议

  1. 练习 1 的答案就在仓库里：路线图让你写一个 Record 类，RMDB 的 RmRecord 就是参考答案（还多了 allocated_ 标志和 Deserialize）。建议先自己写，再对照 rm_defs.h:48-121 找差距——这个对照过程比写本身更有价值。
  2. 阶段一不必碰 transaction_manager.cpp：路线图阶段二才要求读它，但它是全项目最复杂的文件（MVCC + 并发）。阶段一如果读它卡住，正常，别浪费时间，按计划走。

六、阶段一完成标志

  • [ ] 能读懂 src/record/rm_defs.h 和 src/common/common.h 的所有类型定义
  • [ ] 知道 unique_ptr 和裸指针的区别
  • [ ] 能解释 vector::push_back 什么时候会拷贝/移动对象
  • [ ] 练习 1~5 全部完成（练习 5 = 读 src/defs.h 无障碍）

完成后进入 数据库内核学习路线 阶段二：C++ 并发。

数据库内核开发学习全流程

目标：零基础 → 能读懂并修改本仓库（RMDB）的内核代码，为 2026 数据库大赛决赛服务
本仓库：RMDB（C++17 自研关系型数据库，TPC-C 决赛项目）

0. 总览：两条路线

你的情况特殊：决赛就在眼前（时间紧），同时是零基础（底子薄）。所以分两条线：

路线 时间 目标 适合谁
A. 决赛冲刺线 2~3 周 能读懂 RMDB 代码、能改 BUG、能做小优化、会跑测试 马上要比赛
B. 系统学习线 3~6 个月 真正理解数据库内核，能独立设计实现 长期发展

建议组合：先走 A 线拿到"能干活"的能力参加决赛，赛后继续 B 线补地基。本文按 A 线为主编写，B 线作为延伸标注。

学习节奏：每天 3~4 小时，A 线 3 周。每阶段末尾有自测，过不了就回头补。

1. 环境准备（第 1 天，半天）

1.1 你需要什么

工具 用途 说明
WSL2 + Ubuntu 24.04 编译运行 RMDB 项目是 POSIX 代码，Windows 上无法编译
g++ 13 C++ 编译器 Ubuntu 自带
cmake ≥ 3.16 构建 sudo apt install cmake
gdb 调试 sudo apt install gdb
VSCode（Windows 侧） 编辑器 用 Remote-WSL 插件连进 Ubuntu 编辑

1.2 搭建步骤

1.3 自测

  • [ ] cmake --build build 成功
  • [ ] ./build/bin/unit_test 全部通过
  • [ ] 能启动 rmdb 并用 rmdb_client 连上执行 show tables;

2. 阶段一：C++ 基础（第 2~7 天）

RMDB 是 C++17 写的。你不需要精通 C++，但必须能读懂代码。

2.1 学习资源

  • 书：《C++ Primer》（只看前 12 章：变量、字符串、vector、函数、类、拷贝控制）
  • 视频：黑马程序员 C++ 基础（B 站，选"面向对象"部分）
  • 在线练习：https://leetcode.cn/problemset/（做 easy 题练语法）

2.2 必学知识点（按优先级）

优先级 知识点 为什么重要（对应 RMDB 代码）
★★★ 指针、引用、内存 RmRecord.data 是 char*，整个存储层都在操作裸内存
★★★ 类和访问控制 看 RmFileHandle、IxIndexHandle 的封装
★★★ 继承与多态 执行器 AbstractExecutor → SeqScanExecutor 等
★★★ STL 容器 vector（记录缓存）、unordered_map（页表）、map（索引缓存）、set
★★☆ 智能指针 unique_ptr（执行器树、事务）、shared_ptr（AST、可见版本）
★★☆ 模板 std::make_unique<T> 等，够用即可
★★☆ 函数对象/lambda 排序比较器、回调
★☆☆ 字符串处理 SQL 解析、协议编码

2.3 练习（每天 1~2 个）

  1. 写一个类 Record，用 char* 存定长数据，实现拷贝构造/赋值/析构
  2. 写一个链表/动态数组，练指针
  3. 用 vector+unordered_map 实现一个简单索引
  4. 写一个继承体系：Shape → Circle/Rect，练多态
  5. 读 src/defs.h（Rid、ColType 定义）——能读懂就算过关

2.4 自测

  • [ ] 能读懂 src/record/rm_defs.h 和 src/common/common.h 的所有类型定义
  • [ ] 知道 unique_ptr 和裸指针的区别
  • [ ] 能解释 vector::push_back 什么时候会拷贝/移动对象

3. 阶段二：C++ 并发（第 8~11 天）

这是决赛最关键的技术。RMDB 的并发正确性 100% 靠事务管理器里的锁和原子操作，48 个隔离测试全是并发场景。你之前的崩溃（SIGSEGV）就是并发 BUG。

3.1 必学知识点

知识点 对应 RMDB 代码
std::mutex / lock_guard RmFileHandle::record_latch_
std::shared_mutex 读写锁 SmManager::cache_latch_
std::condition_variable WriteShard::writer_released（写者等待）
std::atomic 与 memory_order TransactionManager::newest_committed_write_ts_
死锁与锁顺序 事务管理器里多把锁的嵌套顺序
数据竞争（UB）的后果 你的 SIGSEGV 就是这么来的

3.2 必读代码（读完 = 学会）

  1. src/transaction/transaction_manager.cpp —— 全项目最重要的文件，MVCC 全部实现
  2. src/storage/buffer_pool_manager.cpp —— 缓冲池并发（fetch_page/new_page 的锁外 I/O）
  3. src/system/sm_manager.cpp 的缓存部分 —— 分片锁 index_cache_latches_[64]

3.3 练习

  1. 写一个线程安全的计数器（mutex 版 → atomic 版）
  2. 写一个生产者-消费者队列（condition_variable）
  3. 写一个会死锁的程序，然后用 gdb 分析它为什么卡住
  4. 用 -fsanitize=thread 编译一个故意写错的并发程序，看它怎么报错

3.4 调试工具（必会）

3.5 自测

  • [ ] 能解释 GetVisibleRecord（transaction_manager.cpp:797）的可见性逻辑
  • [ ] 知道 unordered_map 为什么不能无锁并发读
  • [ ] 能说清 memory_order_acquire/release 的用途

4. 阶段三：数据库理论（第 12~16 天）

学理论时对照本仓库代码看，效率翻倍。

4.1 教材与课程

  • 首选：CMU 15-445（https://15445.courses.cs.cmu.edu/fall2024/）—— Andy Pavlo 的《Database Systems》，Bustub 项目与 RMDB 架构几乎一模一样。看视频即可，Project 可选做（时间不够就只看 Lecture 6~18）
  • 中文教材：《数据库系统概念》（机械工业出版社，看 12~18 章）
  • 本仓库配合阅读：docs/P0-P1修复记录.md（记录了这个项目踩过的坑，很有价值）

4.2 理论与代码对照表

理论主题 章节 对应 RMDB 代码
磁盘与页管理 Lecture 6 src/storage/、src/record/
缓冲池 Lecture 7 src/storage/buffer_pool_manager.cpp、src/replacer/
B+ 树索引 Lecture 8~10 src/index/
查询执行（火山模型） Lecture 11~12 src/execution/
查询优化 Lecture 13~14 src/optimizer/
事务与隔离级别 Lecture 16 src/transaction/
并发控制（MVCC） Lecture 17 src/transaction/transaction_manager.cpp
崩溃恢复（WAL/ARIES） Lecture 18 src/recovery/

4.3 必须搞懂的概念（按决赛重要性排序）

  1. 快照隔离（SI）：读旧版本、写写冲突怎么判定（对应 GetVisibleRecord、WaitWriteTurn）
  2. 可串行化（SSI）：rw 边、危险结构、写偏斜（对应 rw_edges_、AddRwEdgeAndCheckDangerous）
  3. WAL 与 ARIES 恢复：redo 已提交、undo 未提交、幂等（对应 log_recovery.cpp）
  4. B+ 树：插入分裂、删除合并、复合键、范围扫描
  5. 火山模型：每个算子一个类，beginTuple/nextTuple/Next 三个方法
  6. TPC-C 负载：NewOrder/Payment/OrderStatus/Delivery/StockLevel 五类事务的语义（赛题第三章）

4.4 自测

  • [ ] 不看代码能画出 RMDB 的架构图（客户端 → portal → 执行器 → 存储）
  • [ ] 能解释 SI 下两个事务同时 UPDATE 同一行会发生什么
  • [ ] 能解释"先写 WAL 再写数据页"为什么必要

5. 阶段四：RMDB 代码精读（第 17~21 天）

顺序 = 依赖顺序：从下往上读。每个文件读完后用自己的话写 3~5 行摘要。

5.1 精读路线（约 15 个文件，每天 3 个）

第 1 层：公共基础

  • src/defs.h：Rid、ColType、RecScan 接口
  • src/common/common.h：Value、Condition、TabCol
  • src/common/context.h：Context（贯穿全链路的执行上下文）

第 2 层：存储

  • src/storage/page.h：页结构（4 字节 LSN 前缀 + 页头）
  • src/storage/disk_manager.cpp：文件 I/O（pread/pwrite）
  • src/storage/buffer_pool_manager.cpp：缓冲池核心（页表、LRU、锁外 I/O）
  • src/replacer/lru_replacer.cpp：LRU 替换

第 3 层：记录与索引

  • src/record/rm_file_handle.cpp：表文件（bitmap + 定长槽 + 空闲页链表）
  • src/record/rm_scan.cpp：全表扫描
  • src/index/ix_index_handle.cpp：B+ 树（插入/分裂/删除）
  • src/index/ix_scan.cpp：索引范围扫描

第 4 层：事务与恢复（重点）

  • src/transaction/transaction_manager.cpp：MVCC + SSI 全部逻辑
  • src/transaction/transaction.h：事务对象（write_set 等）
  • src/recovery/log_manager.cpp：WAL 日志
  • src/recovery/log_recovery.cpp：崩溃恢复（analyze/redo/undo）

第 5 层：执行

  • src/execution/executor_abstract.h：执行器基类
  • src/execution/executor_seq_scan.h：全表扫描执行器（多路归并 + MVCC）
  • src/execution/executor_index_scan.h：索引扫描执行器
  • src/execution/executor_insert.h：插入执行器（冲突检查 + WAL + 索引维护）
  • src/execution/execution_manager.cpp：QL 分发、结果输出
  • src/execution/aggregate_executor.h：聚合快速路径（决赛性能关键）

第 6 层：入口与协议

  • src/rmdb.cpp：服务器主循环（快速路径拦截 + 标准路径）
  • src/wire_protocol.cpp：帧协议（PREPARE_SET/EXEC_BATCH）

5.2 精读方法

  1. 先看头文件（.h）的类成员和函数声明，猜职责
  2. 再看 .cpp 实现，对照 5.1 里的架构图
  3. 用 gdb 打断点跟一遍关键流程（如 insert_record）
  4. 每个文件写 3~5 行中文摘要，存到 docs/reading-notes.md

5.3 自测

  • [ ] 能画出"一条 INSERT 语句从网络到磁盘的完整调用链"
  • [ ] 能画出"一个事务 commit 时发生了什么"（WAL → 写历史 → 释放写者 → 剪枝）
  • [ ] 能解释 32 客户端并发时插入同一张表为什么可能冲突

6. 阶段五：动手实践（第 22~28 天）

从"能读"到"能改"的跨越。按难度递增，每个任务都要编译 + 测试通过。

6.1 练习任务（在 RMDB 上做）

# 任务 难度 涉及文件 参考
1 给 LRU 替换策略加统计日志 ★ src/replacer/ 热身
2 实现 SET enable_nestloop off 时退化为全表扫描 × 全表扫描的 join ★★ executor_nestedloop_join.h 理解执行器
3 给 SeqScan 加一个"每扫描 1000 行打印一次"的调试钩子 ★★ executor_seq_scan.h 理解扫描
4 实现 LIMIT 下推（LimitExecutor） ★★★ 新建执行器 + planner 端到端

6 修一个已知 BUG：CheckSerializableWrite 无锁访问 txn_map（已完成，作为阅读题） ★★★ transaction_manager.cpp 并发
7 写一个 32 并发客户端压测脚本（Python） ★★★ 项目根目录 决赛必备

6.2 测试方法论（必学）

6.3 决赛专项练习

  1. 协议测试：写 Python 脚本模拟 Wire Protocol（握手 → EXEC_STREAM → PREPARE_SET → EXEC_BATCH），对照赛题附件 A 逐字节验证
  2. FLOAT 语义：测 SUM(FLOAT) 的 binary64 累加 + 单次舍入，用 struct.pack('>f', x) 对比位模式
  3. 恢复性能：生成大库 → SIGKILL → 计时重启到 show tables; 就绪（目标 < 90s）
  4. SI 语义测试：写两个连接并发 UPDATE 同一行、验证写写冲突、快照可见性

6.4 自测

  • [ ] 有一个可用的并发压测脚本
  • [ ] 能自己用 ASAN 定位并修复一个并发 BUG

7. 阶段六：决赛冲刺清单（最后 1 周）

对照赛题逐项自查：

  • [ ] 正确性：五类事务、NewOrder 无效商品回滚、Delivery 空队列跳过
  • [ ] 隔离：SI 快照可见性、写写冲突、SSI 立即中止（48 个历史测试）
  • [ ] 聚合：COUNT(DISTINCT) 两种括号写法、join + 去重
  • [ ] FLOAT：binary32 位模式、SUM 双精度累加、±0 归一
  • [ ] 协议：握手字节、AUTO_ABORT、BATCH_RESULT 状态码
  • [ ] 持久化：commit 前 fsync、SIGKILL 后数据完整、90s 内恢复
  • [ ] 性能：32 客户端 warmup 不崩、三类窗口 NewOrder/min 中位数

9. 常见问题

Q：我 C++ 还没学完，能直接看代码吗？
A：能。按"遇到不会的再查"的方式读代码（查 cppreference），比从头学完再读快得多。重点是看懂 src/transaction/transaction_manager.cpp。

Q：决赛只剩几天了，优先做什么？
A：① 环境跑通 + 会跑测试；② 读 transaction_manager.cpp 和 rmdb.cpp 的快速路径；③ 会用 ASAN；④ 有压测脚本。其他理论赛后再补。

Q：我需要精通 SQL 吗？
A：不用。会基本的 SELECT/INSERT/UPDATE/DELETE/CREATE TABLE 就行，TPC-C 的 SQL 都写在赛题里。

Q：学完这些能独立写一个数据库吗？
A：A 线结束可以独立修改维护 RMDB；B 线（加上 C++ 模板元编程、无锁并发、查询优化器）结束后可以设计自己的简单数据库。写生产级数据库需要更长时间，但你已经入门了。

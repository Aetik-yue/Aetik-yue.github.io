C++ 结构体与类：性质、写法与用法

2.1 定义写法

三个要点：

  • struct 关键字 + 结构体名 + 一对 {}；
  • {} 里声明的是成员变量（member），每个成员都要写类型；
  • 结尾的分号经常被忘记，报错信息还会指向下一行代码，非常迷惑人。

定义结构体只是画了一张"图纸"，并不分配内存；真正创建变量时才占用空间。

先看一个反直觉的现象：

CPU 访问内存时按对齐地址读取效率最高，所以编译器会在成员之间塞进填充字节（padding）。基本规则：

  1. 每个成员的起始偏移量必须能被自身大小整除（int 要放在 4 的倍数地址上）；
  2. 结构体总大小必须能被最大成员的大小整除。

顺带一提，空结构体的 sizeof 是 1 而不是 0——C++ 要求每个对象都有独立地址，编译器会塞 1 字节占位。

3.3 C++ 的结构体可以有成员函数

在 C 语言里 struct 只能装数据；到了 C++，struct 完全可以带函数：

这正是关键：C++ 中 struct 和 class 的唯一语法区别是默认访问权限——

成员默认权限 继承时默认权限
struct public public
class private private

除此之外，成员函数、构造函数、继承、多态……两者全部一样。所以"什么时候用哪个"纯粹是约定俗成：

  • 全是公开数据、没有复杂不变量（如坐标点、配置项）→ 用 struct；
  • 数据需要隐藏、有"必须保持正确的规则"（如账户余额不能为负）→ 用 class。

4. 类：带保护的数据 + 行为

4.1 基本写法与访问控制

三种访问说明符：

说明符 类内 派生类 类外
public ✅ ✅ ✅
protected ✅ ✅ ❌
private ✅ ❌ ❌

这就是**封装（encapsulation）**的核心思想：数据藏起来，只通过接口进出。好处是——接口里可以加校验（重量不许为负）、以后改内部实现不影响使用者、出 bug 时嫌疑人范围大大缩小。

参数列表后面的 const 承诺"这个函数不修改任何成员"。只读函数都该加上它，否则 const 对象会调不了你的函数：

判断标准很简单：不修改成员的函数一律标 const。

6.3 static 成员：属于整个类，而不是某个对象

count_ 不属于任何一个西瓜，而是全体共享——常用来做"对象计数器"“全局配置”。静态成员函数因为没有 this，只能访问静态成员。

friend 允许指定某个函数/类访问自己的私有成员。典型用途是给类写 << 输出运算符：

创建 Car 时先构造成员 engine_ 再构造 Car 自己；析构顺序恰好相反。记住这句口诀：构造自内向外，析构自外向内。

9. 小结

  • struct 与 class 在 C++ 中能力完全相同，只差默认访问权限：数据聚合用 struct，需要封装不变量用 class；
  • 结构体的三板斧：聚合初始化、./-> 访问、const T& 传参；
  • 类的三件套：封装（private + 接口）、构造/析构（初始化列表、RAII）、static/const/friend 修饰体系；
  • 内存对齐决定了 sizeof 可能比成员相加更大，成员按大小排能省内存。

C++ 封装、函数重载与运算符重载：性质、写法与用法

系列第三篇。前两篇讲了结构体与类、继承与多态，这篇回到"把类的接口设计好"这件事上：封装决定外界能看到什么，函数重载让同一个名字承接不同入参，运算符重载则让自定义类型用起来像 int 一样自然。三个主题层层递进，全部围绕"接口"二字。

1. 从"接口"说起

一个类的质量，很大程度上取决于它的接口设计：

  • 接口漏了：外界能绕过规则乱改数据，对象随时处于非法状态；
  • 接口杂了：十个函数名干一件事（add、plus、sum……），调用者记不住；
  • 接口涩了：明明是"两筐西瓜合并"这种自然操作，却要调用 basket.mergeWith(other) 而不是 basket + other。

封装治第一种病，函数重载治第二种，运算符重载治第三种。下面一个个来。

2. 封装：藏数据，露接口

2.1 快速复习

private 成员外界摸不到，只能通过 public 接口进出（访问控制表和 protected 详见上一篇 2.1 节）：

2.2 封装保护的是"不变量"

封装的意义常被理解成"安全/私密"，更准确的说法是：保护不变量（invariant）——对象必须始终成立的规则。

balance_ 一旦私有，"余额永远非负"这条规则就有了唯一的执行点——所有修改都得过接口的检查。数据公开时，规则散落在每个使用者手里，谁都有机会破坏它。

判断"这个成员要不要 private"的实用标准：它有没有必须成立的规则。有 → private + 接口；没有（比如坐标点的 x、y）→ public 也无妨，这正是 struct 存在的理由。

2.3 假封装：无脑 getter/setter

最常见的反模式是给每个成员配一对 getter/setter，等于把数据公开换了个马甲：

w.set_weight(-999) 畅通无阻，不变量形同虚设。检查清单：

  • setter 里该有校验，没有规则可校验就不需要 setter；
  • getter 命名直接用名词（weight() 而不是 get_weight()），C++ 标准库也是这个风格；
  • 更好的思路是少问对象要数据，多让对象做事：与其 if (melon.weight() > 5) melon.set_weight(melon.weight() - 1);，不如让对象提供 melon.cut(Weight(1))。

2.4 别把内部泄露出去

返回私有成员的引用或指针，封装会被 silently 击穿：

外界拿到非 const 引用后，basket.items().clear()、塞进任何东西都无人拦截。原则：

  • 返回容器内容时给 const 引用（只读视图），或干脆返回值/提供只读接口（count()、at(i)）；
  • 常见例外是标准库的 std::vector::operator[]——它选择效率并把责任交给使用者，写业务代码时别照抄这态度。

3. 函数重载：一名多用

3.1 写法与重载决议

同一个作用域里，函数名相同、参数列表不同的多个函数构成重载：

调用时编译器按实参在编译期选出唯一匹配（这叫静态多态/重载决议）：先找完全匹配，找不到再看标准转换（如 int → double），再找不到看用户自定义转换；要是两条路"一样好"，直接报二义性错误。

3.2 什么能、什么不能构成重载

类成员函数有个容易混的点：成员函数的 const 限定符参与重载——这就是标准库 begin() 有 const/非 const 两版的原理：

const 对象调只读版，非 const 对象调可改版——同一个 at 名字，两种权限，正好配合 2.4 节的封装原则。

3.3 重载与默认参数：会打架

两者都能"少写几个函数"，但混用容易撞车：

选型经验："缺省值固定"用默认参数，"处理类型/形态确实不同"用重载，别让一个参数既像缺省又像重载。

3.4 为什么 C++ 能重载而 C 不能

编译器会对函数名做名字改编（name mangling）——把参数类型编进符号名，print(int) 和 print(double) 在目标文件里就是两个不同符号。C 不改编，同名即冲突。这也解释了 extern "C" 的作用：关闭改编，让 C++ 代码能链接 C 库——代价自然是那份代码不能重载。

4. 运算符重载：让类型"说人话"

4.1 什么时候值得重载运算符

自定义类型上频繁做算术、比较时，函数名版本很啰嗦：

但运算符重载是语法糖不是魔法：只有当"这个运算符对这个类型有自然的数学含义"时才值得用——重量相加、金额比较都很自然；给 Logger 重载 % 就是炫技，直接写 logger.log(x) 更清楚。

4.2 两种写法：成员版与非成员版

选择规则就一条：左操作数不是本类对象时，只能用非成员版。最典型的是输出流——cout << w 的左操作数是 ostream，所以 operator<< 必须是非成员：

（把左操作数按值接收还有个好处：配合非 explicit 的转换构造函数，w + 2.0、2.0 + w 这类与内置类型混合的运算也能工作。）

4.4 前置与后置自增：int 占位参数区分

++i 和 i++ 是两个不同的运算符，靠一个占位 int 参数区分重载：

后置版要多做一次拷贝——这也是"循环里写 ++i 优于 i++"这条老建议的出处（对 int 无所谓，对重对象有区别）。

4.5 不可重载的运算符，与两个警告

不能重载（保持语言底层语义）：::（作用域）、.（成员访问）、.*（成员指针访问）、?:（三目）、以及 sizeof、typeid 等。

两个易踩的语义警告：

  • 重载 &&、|| 后短路求值失效——两个操作数都会先求值，完全违背直觉，别重载它们；
  • 重载的运算符优先级和结合性不变：你定义的 w1 + w2 * w3 仍然先算 *，设计语义时别指望改变这一点。

写腻了 4.3 那四行比较？C++20 的三路比较运算符 <=>（太空船运算符）加上 = default，让编译器替你生成：

注意 == 要单独 default 一份（它和 <=> 的生成规则是分开的）。成员都是内置类型或自带比较的类型时，这套写法一步到位。

4.7 explicit：管住隐式转换

单参数构造函数默认允许隐式转换，Weight w = 5.0; 会静默通过——有时方便，有时是 bug 源头。加 explicit 后必须显式写 Weight(5.0)：

经验：单参数构造函数默认加 explicit，确认隐式转换确实好用（如 std::string 从字符串字面量转换）再摘掉。

6. 常见坑速查

坑 现象 / 解法
无脑 getter/setter 假封装，不变量无人守卫；setter 必须带校验
返回私有成员的非 const 引用 封装被击穿；返回 const 引用或提供只读接口
试图重载 ::、.、.*、?: 不允许重载，改用普通函数
operator+ 返回引用 返回局部变量的引用是悬垂引用，按值返回
只写 == 忘了 != 两两配对，用 == 推出其余比较
后置 ++ 忘了返回旧值 先备份再自增；int 只是占位参数
重载 && / || 短路求值失效，别这么做
单参数构造函数忘加 explicit 意料之外的隐式转换；默认加上
默认参数 + 重载撞车 price(double, double=7.9) 与 price(double) 二义性

7. 小结

  • 封装守的是不变量：数据 private 化不是目的，让"必须成立的规则"有唯一执行点才是；getter 少而精，setter 必校验，别泄露内部引用；
  • 函数重载靠参数列表区分（返回值和顶层 const 不算数），成员函数的 const 限定符参与重载；决议发生在编译期，撞出二义性就报错；
  • 运算符重载三件套：左操作数不是本类就写非成员版、复合赋值打底实现算术族、== 打底实现比较族；C++20 一行 <=> 写全比较；
  • 接口设计的目标只有一个：让调用代码读起来像它要做的事。

系列三篇到这里把面向对象的主干走完了——结构体与类 打地基、继承与多态 搭框架、本篇修接口。下一站是模板与 STL：当"重载"升级成"对任意类型都成立"，泛型编程的大门就打开了。

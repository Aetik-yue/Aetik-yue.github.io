C++ 继承与多态：性质、写法与用法

上一篇 C++ 结构体与类 讲了怎么把数据和行为打包成类。这篇解决两个新问题：怎么让一个类复用并扩展另一个类（继承），以及怎么让不同的类对同一个调用给出不同的反应（多态）。老规矩，全文代码可直接复制运行。

2. 继承的基本写法

2.1 语法与三种继承方式

继承方式决定"基类成员在我这里最高是什么权限"：

基类成员 public 继承 protected 继承 private 继承
public public protected private
protected protected protected private
private 不可见 不可见 不可见

要点：

  • 基类的 private 成员被继承了但不可直接访问，派生类只能通过基类的 public/protected 接口间接使用；
  • protected 是给继承准备的访问级别：类外碰不到，但派生类的成员函数里可以用；
  • 实践中 95% 的场景用 public 继承——它才表达"is-a"。protected/private 继承表达的是"用它的实现"，很少见，本文后续只讨论 public 继承。

2.2 继承 vs 组合：is-a 还是 has-a？

写代码前先问自己关系是什么：

  • “是一种” → 继承：西瓜是一种水果 → class Watermelon : public Fruit；
  • “有一个” → 组合：汽车有一个引擎 → 成员变量 Engine engine_;（上一篇 6.5 节）。

拿不准时选组合。继承是强耦合——基类一改，所有派生类都受影响；组合只是"借用"，灵活得多。

5. 多态：同一个调用，不同的反应

5.1 问题引入：没加 virtual 时，“看指针不认人”

默认情况下函数调用是静态绑定：编译器看指针的声明类型（Animal*），不看它实际指着什么。这显然违背直觉。

5.2 virtual：开启动态绑定

给基类函数加上 virtual，调用就推迟到运行时按对象的实际类型分发：

三个要点：

  1. virtual 只需写在基类上，派生类自动为虚；

  2. 派生类重写的函数签名必须完全一致（含 const），建议总是加 override——签名对不上时编译器会当场报错，而不是静默造出一个新函数：

  3. 一旦某个函数是虚的，析构函数也应设为虚（第 7 节细说）。

原理一句话：含虚函数的类会有一张虚函数表（vtable），对象里藏一个指针指向它；调用虚函数时先"查表"再跳转，所以运行时能按实际类型找到正确的版本。（想深挖可以搜 “C++ vtable”，面试常考。）

5.3 多态的前提：指针或引用

多态只在使用指针或引用时发生。直接按值拷贝会把派生类部分切掉：

Animal copy = dog; 只拷贝 Animal 那部分内存——派生类新加的成员被"切"掉了，当然也多态不起来。这也是为什么多态函数的参数一律写成 const Base&。

5.4 典型用法：统一容器处理一族对象

一个循环、同一个接口，行为却随实际类型变化——这就是多态的价值：新增一种动物时，循环代码一个字都不用改。

6. 纯虚函数与抽象类

有些基类天生就该是"图纸"：Animal 这个概念本身没法叫，能叫的只有具体的猫猫狗狗。把函数写成纯虚函数（= 0），类就变成抽象类：

规则：

  • 抽象类不能创建对象，但可以有指针和引用（多态照样用）；
  • 派生类必须重写所有纯虚函数，否则自己也是抽象类；
  • 纯虚函数可以给出函数体（类外定义，供派生类 Animal::speak() 显式调用），但常见用途就是定义接口。

7. 虚析构函数：最容易踩的坑

delete 基类指针时，如果析构函数不是虚函数，行为是未定义的——典型后果是派生类那部分资源（它 new 出来的内存、打开的文件）永远不会释放，内存泄漏。加上 virtual 后，delete 会先调 Dog 的析构、再自动调 Animal 的析构，链子完整。

规则：一个类只要有虚函数，析构函数就必须是虚的。 反过来，类没有虚函数、也不打算被继承（比如 std::string），就不用虚析构，白付虚表开销。

8. 更多性质与使用规则

8.1 final：关门谢客

final 的价值不是防自己，是防后人：明确表达"这条继承/重写路线到此为止"，也让编译器能放心做去虚化优化。

8.2 构造/析构函数里不要调用虚函数

构造 Dog 时先执行基类构造函数，此刻派生类部分还不存在——虚函数退化成基类版本。不是编译错误，是符合逻辑的"静默不符合直觉"，所以靠约定规避：构造函数只做纯粹的初始化。

8.3 运行时类型查询：dynamic_cast 一笔带过

需要它通常说明接口设计缺了东西（比如该把 fetch 提成虚函数），优先改设计；确有合理场景再用。配套的 typeid 可以取实际类型名，调试时偶尔有用。

10. 常见坑速查

坑 现象 / 解法
基类析构函数忘写 virtual delete 基类指针泄漏派生类资源；有虚函数的基类析构必虚
按值传递/拷贝多态对象 对象切片，派生部分丢失；一律 const Base&
重写函数签名对不上（多/少 const） 静默变成新函数；重写一律加 override
构造函数里调用虚函数 拿到的是基类版本；构造函数只做初始化
忘了纯虚函数没实现完 派生类还是抽象类，实例化时报错
派生类同名函数"连坐"隐藏基类重载 using Base::f; 引入，或 Base::f() 显式调用

11. 小结

  • 继承表达 is-a：class D : public B；派生类先构造基类再构造自己，析构相反；
  • 多态三要素：虚函数、通过基类指针/引用调用、运行时动态绑定；override 把签名错误从"静默 bug"变成"编译报错"；
  • 抽象类靠纯虚函数定义接口，派生类补齐所有纯虚才能实例化；
  • 记住三条铁律：析构要虚、传参用引用、重写加 override。

到这里，C++ 面向对象的三板斧——封装（上一篇）、继承与多态（本篇）就齐了。下一步自然的方向是模板与泛型编程（template、STL 背后的思想），以及用智能指针和 RAII 把资源管理做扎实——这些留到后面的文章再聊。

1、数据库系统概述

发表于2026-05-15|更新于2026-09-01|数据库内核
|总字数:1.4k|阅读时长:4分钟|浏览量:

分为三大块，分别为数据库历史发展、系统分类、系统概述

1、在没有数据库的日子

在没有数据库的时候，应用程序直接操作底层文件

  • 利用文件系统将数据持久化
  • 自己设计并发控制
  • 自己设计故障恢复
  • 自己定义文件格式和访问方式
    • 应用来设计数据的逻辑结构
    • 应用来设计数据物理结构、存储结构、存取方式、输入方法等
      数据库的迁移会很辛苦

2、抽象

2.1、接口

  • 数据定义语言DDL
  • 数据查询语言SQL
  • 数据操作语言DML

2.2、实现

  • 实现DDL，DML，SQL
  • 持久化–尤其是海量数据
  • 故障恢复能力
  • 并发控制与事务管理（隔离性和原子性）

3、早期数据库管理系统

  • 层次模型
  • 网状模型
  • 缺点
    • 没有高级查询语言
    • 操作复杂

4、关系数据库系统

1970年Edgar F. Codd提出

  • 优点
    • 建立在严格的数学概念的基础上，有理论基础
    • 数据模型清晰–所有模型都使用关系来表示
    • 接口非常清晰，逻辑层和物理层非常清晰的剥离

逻辑层
物理层 —关键

  • 数据存储系统
    • API访问
    • 不需要预定义模式
    • 分布式支持
    • 对象存储

5.数据库架构

三大部分

  • SQL引擎
  • 存储引擎
  • 事务引擎

5.1、AI分析：

这张图完整地展示了数据库处理一条 SQL 语句从**“发过来”到“出结果”的全部内部步骤。我们可以把它从上到下分为查询处理和底层存储与事务**两个大阶段，结合图中的箭头来理解：

第一阶段：查询处理 (上半部分 / 中间层)

这一层的核心任务是：把人类写的 SQL 变成机器可以跑的代码，并尽量利用缓存来“走捷径”。

  1. Parser (解析器)：检查 SQL 语法是否正确。
  2. Query result cache (查询结果缓存)：看看之前有没有人跑过一模一样的 SQL。如果有，直接从缓存拿结果返回（图上标记的“命中”），省去所有后续繁琐步骤。
  3. Resolver (解析器)：检查 SQL 里的表名、列名存不存在，把逻辑捋顺。
  4. Plan cache (计划缓存)：有没有为这个 SQL 算好的“执行计划”？（图上第二个“命中”）。如果命中了，就不需要再去算怎么跑最好了。
  5. Transformer / Optimizer (转换器 / 优化器)：如果没有命中缓存，数据库会自己动脑子。
    • Transformer：重写 SQL，比如把能提前过滤的条件推下去。
    • Optimizer：利用复杂的数学算法算出来“走哪个索引更快”、“是应该先连 A 表还是 B 表”。
  6. Code Generator (代码生成器)：把算出来的“最优计划”变成机器底层的代码。
  7. Executor (执行器)：最后，真正去执行这段代码。

第二阶段：底层存储与事务 (下半部分)

当执行器需要读数据或写数据时，就进入了事务和存储层。这一层的核心任务是：保证数据不丢、不乱、且可以并发处理。

  1. 事务管理器 (Transaction Manager)：它是存储层的“大脑”，负责协调下面的组件。
  2. 并发控制 (Concurrency Control)：
    • Lock (锁)：传统模式，一个人写数据时把别人锁在外面。
    • MVCC (多版本并发控制)：现代数据库的高级模式（OceanBase 等强力推荐）。它允许读写不互相阻塞，读的人读快照，写的人写新版本，效率非常高。
  3. 日志与恢复 (Logging & Recovery)：确保数据安全。比如突然断电重启，系统能通过日志恢复到断电前的最后一刻（防止数据丢失）。
  4. Buffer Pool (缓冲池) & 存储管理器：
    • Buffer Pool：内存里的“中转站”。数据不直接写硬盘，先放这里攒一波，提高速度。
    • Storage Manager：真正负责把数据写到硬盘的存储层。
  5. Catalog (数据字典)：旁边挂着的 Catalog 记录着数据库里有哪些表、字段类型等元数据。Resolver 运行时必须找它核对。

亮点总结（图上最精髓的地方）：

  • 两个“命中”回旋镖：图上特别画了“Query result cache”和“Plan cache”的命中回退箭头。这告诉我们：数据库设计非常强调“缓存”。 同样的 SQL 跑第二遍，可能只要毫秒级，因为它直接绕过了复杂的解析和优化过程。
  • MVCC vs 锁：图底部的分叉展示了现代数据库解决高并发冲突的两大流派。像 OceanBase、TiDB 这样的分布式数据库，非常依赖 MVCC 来实现超高吞吐。

6.关系数据库=存储+事务+SQL

  • 存储：关系数据库的数据结构
  • 事务：关系数据库的算法
  • SQL：关系数据库操作的描述语言

6.1、存储

工业界的两种基础的数据结构

  • 哈希表：O(1)，支持put/get，不支持范围scan
  • B+树：O(logn)，支持put/get，也支持范围scan

6.2、事务（数据库中最难的部分）

事务要么成功要么失败

6.3、SQL

相当于一层基于关系代数的接口
数据库内部有专门的一块SQL引擎来实现这个接口
